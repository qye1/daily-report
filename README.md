# Автоматический ежедневный отчет по продажам


1. **Проверки данных** (`checks.py`) до расчета: свежесть, объем заказов против обычного для дня недели, дубли, пропуски в регионе и категории, неположительные суммы, даты из будущего. Каждая проверка возвращает ok, warn или fail.
2. **Если есть fail, отчет не собирается.** Вместо него создается `FAILED.txt` с причиной, код возврата 2. Лучше не отправить отчет, чем отправить неверные цифры.
3. **Расчет** (`metrics.py`): выручка, заказы, средний чек и покупатели против такого же дня неделей раньше, последние 7 дней, с начала месяца против того же числа прошлого месяца, разрезы по регионам и категориям с вкладом в изменение.
4. **Аномалия:** выручка дня сравнивается с медианой тех же дней недели за 8 прошлых недель, масштаб считается по MAD с нижней границей, чтобы ровная история не давала ложных тревог.
5. **Excel** (`build_excel.py`): лист «Сводка» с ячейкой даты B2, которую можно менять, и формулами `INDEX/MATCH`, `SUMIFS`, `EDATE`; лист «Дни», регионы, категории и проверки. Всего больше 200 формул и график. Числа в формулах сверены с pandas.
6. **HTML письмо** (`build_html.py`): карточки показателей, выводы текстом, график, таблицы, статусы проверок. Читается и на телефоне.
7. **Письмо** (`mailer.py`): `.eml` с HTML телом и Excel во вложении. Реальная отправка только с флагом `--send` и настройками в переменных окружения `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`.

Код возврата: 0 все хорошо, 1 отчет собран с предупреждениями, 2 данные плохие и отчета нет. Повторный запуск за ту же дату перезаписывает результат (тест проверяет, что отчет получается тем же самым).

## Запуск

```bash
pip install -r requirements.txt
python report.py --date 2026-10-21     
pytest
```

Без `--date` берется вчерашний день. В папке `reports` уже лежат два готовых примера: 21 октября (обычный день) и 18 октября (заложенный провал выручки, отчет помечает его как аномалию).

## Запуск 

Планировщик заданий, команда в PowerShell:

```powershell
schtasks /Create /SC DAILY /ST 08:30 /TN "DailyReport" /TR "C:\path\to\.venv\Scripts\python.exe C:\path\to\daily-report\report.py"
```

Проверить задание: `schtasks /Query /TN "DailyReport"`. Результат каждого запуска смотрите в `reports\run.log`. В Linux и WSL то же самое делает cron: `30 8 * * * /path/.venv/bin/python /path/report.py`.

## Что подключать к данным

Нужна таблица `orders` с колонками `order_id, order_ts, order_date, customer_id, region, category, qty, amount, status` в SQLite. Для другой базы поменяйте `checks.load_orders`. Пороги проверок, число недель для аномалий и получатели письма лежат в `config.json`.
